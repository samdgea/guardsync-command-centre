# Prompt: Membangun Aplikasi Frontend "GuardSync Command Centre" (Next.js)

> Prompt ini sudah disesuaikan dengan **API_DOCUMENTATION_COMMAND_CENTRE.md** (backend Laravel 12, Command Centre khusus role `SUPER_ADMIN` & `ADMIN`). Gunakan bersama file pendamping `GuardSync-API-Endpoints-Auth.md` untuk detail endpoint & autentikasi. Jangan mengarang endpoint/field baru di luar kedua referensi ini.

---

## 1. Konteks Proyek

**GuardSync Command Centre** adalah web dashboard untuk `SUPER_ADMIN` dan `ADMIN` mengelola & mengawasi operasional satpam lapangan secara terpusat: manajemen site/lokasi, checkpoint & QR patroli, inventaris pos, review laporan kunjungan patroli (termasuk insiden `WASPADA`/`DARURAT`), pemantauan sesi patroli aktif secara real-time, serta pengawasan buku mutasi (logbook) shift.

**Backend:** Laravel 12 (PHP 8.4), dengan **catatan penting**: routing **tidak** memakai prefix `/api/`. Contoh: `POST {baseUrl}/auth/login`, bukan `/api/auth/login`.

---

## 2. Tech Stack

- **Framework**: Next.js 14+ (App Router, TypeScript strict mode)
- **Styling**: Tailwind CSS + shadcn/ui (Radix primitives)
- **State/Data**: TanStack Query (server state, caching, pagination) + Zustand (auth state, site context, UI state)
- **Form & Validasi**: React Hook Form + Zod (samakan pesan validasi dengan `Accept-Language: id`)
- **HTTP Client**: Axios dengan interceptor (lihat §7)
- **Peta**: Leaflet atau Mapbox GL JS (Map Picker untuk latitude/longitude site & checkpoint, visualisasi radius geofence)
- **QR & Print**: `qrcode`/binary image dari endpoint `GET /checkpoints/{id}/qr`, layout cetak stiker A4
- **Chart**: Recharts (untuk `/reports/summary` & `/reports/compliance`)
- **Auth**: Custom JWT (access token pendek + refresh token sekali pakai 7 hari) — lihat §7 dan file endpoint

---

## 3. Role & Site Scoping (WAJIB DIIMPLEMENTASIKAN DENGAN BENAR)

Aplikasi ini melayani 2 role: `SUPER_ADMIN` (scope GLOBAL) dan `ADMIN` (scope ASSIGNED, terikat `site_assignments`). Meskipun role `SUPERVISOR` dan `OFFICER` ada di sistem, mereka **bukan** pengguna Command Centre ini (mobile-app oriented / review-only pada endpoint tertentu).

Aturan yang harus tercermin di UI:
- `SUPER_ADMIN`: bisa lihat & kelola semua site, buat/hapus site, buat user role apapun.
- `ADMIN`: hanya bisa lihat/kelola site yang di-assign kepadanya (dari `GET /auth/me` → `assignments` atau `GET /sites`). Tidak boleh membuat/menghapus site. Tidak boleh membuat user dengan role `ADMIN`/`SUPER_ADMIN`. Percobaan akses `siteId` di luar assignment akan ditolak backend dengan `403 Forbidden` — frontend harus mencegah ini juga secara preventif (client-side guard) dan menampilkan pesan yang sesuai jika tetap terjadi.

Referensi lengkap matriks akses ada di `GuardSync-API-Endpoints-Auth.md` §3.

## 5. Modul & Halaman (mengikuti peta modul resmi di dokumentasi)

### 5.1 Auth
- Login (`/login`): form `identifier` (NIK/email) + `password`, validasi Zod, tampilkan error field dari envelope `data` saat `400`.
- Profile & Change Password (`/profile`): form ganti password (`currentPassword`, `newPassword`, `newPassword_confirmation`).

### 5.2 Live Command Centre
- **Live Overview Dashboard** (`/dashboard`): metric counters (total visits, insiden darurat, % kepatuhan) dari `GET /reports/summary`; grid sesi patroli aktif dari `GET /patrols/sessions/active`; quick alert feed untuk kunjungan `WASPADA`/`DARURAT`.
- **Realtime Map View** (`/monitoring/map`): tampilkan sesi patroli aktif di peta. Dokumentasi tidak menyebutkan WebSocket — implementasikan polling `GET /patrols/sessions/active` secara berkala (mis. via TanStack Query `refetchInterval`).

### 5.3 Master Data Management
- **Sites** (`/sites`): tabel + search/filter, drawer create/edit dengan Map Picker & slider radius geofence, dialog assign/remove officer (`POST`/`DELETE /sites/{siteId}/officers`). Tombol "Tambah Site"/"Hapus Site" **hanya tampil untuk `SUPER_ADMIN`**.
- **Checkpoints** (`/checkpoints`): filter by site, modal add/edit, modal konfirmasi rotate QR, modul preview cetak kartu QR (ambil dari `GET /checkpoints/{id}/qr`, binary PNG).
- **Inventory** (`/inventory`): master alat per pos, filter wajib `siteId`.

### 5.4 User & Officer Management (`/users`)
- Tabel user dengan role badge & toggle aktif.
- Modal tambah/edit user: sembunyikan opsi role `SUPER_ADMIN`/`ADMIN` di form jika user login adalah `ADMIN`.
- Dialog reset password cepat (`POST /users/{id}/reset-password`).

### 5.5 Incident & Patrol Review Desk (`/reports/visits`)
- Filter bar: `siteId`, `condition` (`AMAN`/`WASPADA`/`DARURAT`), `reviewStatus`, rentang tanggal.
- Tabel audit kunjungan dengan popover foto.
- Bulk action bar (checkbox multi-baris → `PATCH /reports/visits/bulk-review`, maksimal 200 ID).
- Modal detail insiden: timeline `statusLogs` + foto resolusi penuh (lightbox).
- Tombol export CSV (`GET /reports/visits/export`, trigger file download).

### 5.6 Analytics & Executive Reporting (`/reports`)
- Summary charts dari `/reports/summary` (breakdown kondisi & status review).
- Compliance chart/gauge dari `/reports/compliance` (per site & per officer).

### 5.7 Digital Mutasi & LogBook Hub (`/logbooks`)
- Tabel shift handover, filter `siteId`/`status`/`date`.
- Detail logbook: rekap cek fisik inventaris (kondisi `BAIK`/`RUSAK`), dan catatan peristiwa/kejadian (`/logbooks/{id}/entries`) dengan filter kategori & rentang tanggal.

## 6. Komponen Khusus yang Wajib Dibangun

### 6.1 Site Context Switcher & Route Guard (KRITIS)
- Lokasi: top bar navigasi.
- `SUPER_ADMIN`: dropdown "Semua Site (Global View)" + daftar seluruh site, bisa switch bebas.
- `ADMIN`: dropdown hanya berisi site dari `assignments`. Jika hanya 1 site, tampilkan sebagai badge tetap (locked context), bukan dropdown.
- Simpan `selectedSiteId` di Zustand store; setiap query data (checkpoints, inventory, reports, sessions, logbooks) wajib menyertakan filter ini.
- Client-side route guard: cegah `ADMIN` mengakses URL dengan `siteId` di luar `assignments` (misal paste URL manual) → redirect ke dashboard + notifikasi "Anda tidak memiliki izin mengakses situs ini."

### 6.2 Map Picker (Leaflet/Mapbox)
- Untuk input latitude/longitude saat create/edit Site & Checkpoint, dengan visualisasi circle radius geofence (`radiusMeters`).

### 6.3 QR Code Batch Sticker Generator
- Ambil binary image dari `GET /checkpoints/{id}/qr`.
- Template stiker siap cetak (A4/label): logo + nama site + nama checkpoint + QR image.

### 6.4 Photo Lightbox & Timeline Audit
- Viewer foto resolusi tinggi untuk bukti temuan `WASPADA`/`DARURAT`.
- Timeline visual untuk `statusLogs` (siapa mengubah status, kapan, catatan).

### 6.5 Role Condition Guard (UI RBAC)
- Sembunyikan/nonaktifkan aksi berikut jika login sebagai `ADMIN`: "Tambah Site Baru", "Hapus Site", opsi role `SUPER_ADMIN`/`ADMIN` di form user.
- Server tetap jadi sumber kebenaran (403 selalu ditangani dengan baik di UI), guard di frontend hanya untuk UX.

## 7. Integrasi API (WAJIB Mengikuti Pola Ini)

### 7.1 Response Envelope
Semua response berbentuk:
```json
{ "success": true, "message": "...", "data": ..., "pagination"?: {...} }
```
Buat helper `unwrap<T>(response)` di `lib/envelope.ts` agar semua pemanggilan API di `features/*` mengembalikan `data` (dan `pagination` jika ada) secara konsisten, dan melempar error yang membawa `message` + detail validasi jika `success: false`.

### 7.2 Axios Instance & Interceptor
```typescript
// lib/api-client.ts
import axios from 'axios';

export const api = axios.create({
  baseURL: process.env.NEXT_PUBLIC_API_URL, // TANPA /api di akhir
  headers: {
    'Content-Type': 'application/json',
    'Accept': 'application/json',
    'Accept-Language': 'id',
  },
});

api.interceptors.request.use((config) => {
  const token = useAuthStore.getState().accessToken;
  if (token) config.headers.Authorization = `Bearer ${token}`;
  return config;
});

api.interceptors.response.use(
  (res) => res,
  async (error) => {
    const original = error.config;
    if (error.response?.status === 401 && !original._retry) {
      original._retry = true;
      try {
        const refreshToken = useAuthStore.getState().refreshToken;
        const { data } = await axios.post(`${api.defaults.baseURL}/auth/refresh`, { refreshToken });
        useAuthStore.getState().setTokens(data.data.accessToken, data.data.refreshToken);
        original.headers.Authorization = `Bearer ${data.data.accessToken}`;
        return api(original);
      } catch {
        useAuthStore.getState().clearAndRedirectToLogin();
        return Promise.reject(error);
      }
    }
    return Promise.reject(error);
  }
);
```
- **Refresh token bersifat one-time use** — pastikan tidak ada race condition (dua request 401 bersamaan memicu dua kali refresh). Gunakan mutex/pending-promise pattern agar refresh hanya dieksekusi sekali.
- Simpan `accessToken` di memory/Zustand state; `refreshToken` di `localStorage` atau, jika backend mendukung, `httpOnly cookie` (lebih aman — konfirmasikan ke tim backend).

### 7.3 Referensi Endpoint
Semua path, method, role akses, dan payload mengikuti `GuardSync-API-Endpoints-Auth.md`. Jangan menambah endpoint yang tidak terdaftar di file tersebut.

## 8. Non-Functional Requirements

- TypeScript strict, hindari `any`.
- Tangani semua kode status: `400` (tampilkan error per-field dari `data`), `401` (auto-refresh, lalu logout jika gagal), `403` (halaman/komponen "akses ditolak", termasuk khusus untuk cross-site `ADMIN`), `404`, `500` (fallback error state + retry).
- Loading skeleton & empty state di semua tabel/list.
- Responsive: prioritas desktop/tablet (dipakai di ruang kontrol/kantor).
- Aksesibilitas: label form jelas, kontras cukup, navigasi keyboard di komponen interaktif (modal, drawer, dropdown).
- `.env.example` berisi `NEXT_PUBLIC_API_URL` (tanpa `/api`), Map API key (jika pakai Mapbox).
