# GuardSync Command Centre — Endpoint Krusial & Autentikasi (Quick Reference)

> Ringkasan cepat diekstrak dari `API_DOCUMENTATION_COMMAND_CENTRE.md` (v1.0.0, backend Laravel 12). Untuk detail request/response body lengkap per endpoint, rujuk dokumen sumber tersebut. File ini untuk dipakai bersama `GuardSync-Command-Centre-Frontend-Prompt.md` saat membangun integrasi API.

## 1. Konfigurasi Dasar

| Item | Nilai |
|---|---|
| Base URL (dev) | `http://localhost:8000` |
| Base URL (prod) | `https://api.guardsync.yourdomain.com` |
| ⚠️ Routing | **TIDAK** memakai prefix `/api/`. Contoh benar: `POST {baseUrl}/auth/login` |
| Format | JSON, kecuali `GET /checkpoints/{id}/qr` (PNG) & `GET /reports/visits/export` (CSV) |

**Headers wajib di setiap request:**

| Header | Nilai | Keterangan |
|---|---|---|
| `Content-Type` | `application/json` | Wajib untuk `POST`/`PATCH`/`PUT` |
| `Accept` | `application/json` | Pastikan response JSON |
| `Authorization` | `Bearer <accessToken>` | Wajib untuk semua endpoint terproteksi |
| `Accept-Language` | `id` (default) atau `en` | Bahasa pesan `message` di response |

## 2. Autentikasi & Token Lifecycle

- **Skema**: Custom JWT (HMAC-SHA256), bukan guard default Laravel.
- **Access Token**: TTL pendek (5 menit–1 jam), dipakai di header `Authorization: Bearer`.
- **Refresh Token**: string acak 64 karakter, **one-time use** (setiap dipakai, langsung di-revoke & diganti pasangan baru), kedaluwarsa 7 hari.
- **Wajib** implementasi mutex/pending-promise saat auto-refresh agar tidak terjadi dua refresh bersamaan (karena sifatnya sekali pakai).

### 2.1 Login
```
POST /auth/login
Akses: Publik
```
**Body:** `{ "identifier": "EMP-ADMIN-01 atau email", "password": "min 8 karakter" }`
**Response 200:** `{ success, message, data: { accessToken, refreshToken } }`

### 2.2 Refresh Token
```
POST /auth/refresh
Akses: Publik (mengirim refreshToken)
```
**Body:** `{ "refreshToken": "..." }`
**Response 200:** pasangan `accessToken` + `refreshToken` baru (token lama otomatis hangus).

### 2.3 Get Profil Login
```
GET /auth/me
Akses: SUPER_ADMIN, ADMIN
```
**Response 200 data:** `{ id, employeeId, email, name, role, active, assignments: [...] }`
→ `assignments` inilah sumber data untuk Site Context Switcher pada role `ADMIN`.

### 2.4 Ganti Password Sendiri
```
PATCH /auth/change-password
Akses: SUPER_ADMIN, ADMIN
```
**Body:** `{ currentPassword, newPassword, newPassword_confirmation }`

### 2.5 Logout
```
POST /auth/logout
Akses: SUPER_ADMIN, ADMIN
```
**Body (opsional):** `{ "refreshToken": "..." }` → revoke token di server.

## 3. RBAC & Site Scoping

4 role sistem: `SUPER_ADMIN` (global), `ADMIN` (assigned-only, tidak cross-site), `SUPERVISOR` (review, bukan user Command Centre ini), `OFFICER` (mobile app, bukan user Command Centre ini).

**Aturan inti:**
- `SUPER_ADMIN`: akses semua site, bisa `POST /sites`, `DELETE /sites/{id}`, buat user role apapun.
- `ADMIN`: hanya akses site di tabel `site_assignments` miliknya. Request dengan `siteId` di luar assignment → **403 Forbidden** (`"Site not assigned"`). Tidak boleh `POST /sites`, `DELETE /sites/{id}`, atau membuat user role `ADMIN`/`SUPER_ADMIN` (403 `"Hanya super admin yang dapat membuat admin"`).

| Fitur | Endpoint | SUPER_ADMIN | ADMIN |
|---|---|:---:|:---:|
| Buat/Hapus Site | `POST/DELETE /sites` | ✅ | ❌ |
| Lihat/Edit Site | `GET/PATCH /sites` | ✅ semua | 🔒 assigned only |
| Assign/Hapus Officer ke Site | `POST/DELETE /sites/{id}/officers` | ✅ semua | 🔒 assigned only |
| Buat User role ADMIN/SUPER_ADMIN | `POST /users` | ✅ | ❌ |
| Buat User role SUPERVISOR/OFFICER | `POST /users` | ✅ | ✅ |
| Checkpoints, Inventory, Reports, LogBooks | berbagai | ✅ semua site | 🔒 assigned only |

## 4. Format Response Envelope

**Sukses (tanpa pagination):**
```json
{ "success": true, "message": "...", "data": { } }
```
**Sukses (dengan pagination):**
```json
{ "success": true, "message": "...", "data": [ ], "pagination": { "page": 1, "limit": 10, "total": 54, "totalPages": 6 } }
```
**Gagal:**
```json
{ "success": false, "message": "...", "data": null }
```
**Gagal — Validasi (400):**
```json
{ "success": false, "message": "Validasi gagal", "data": { "employeeId": ["The employee id field is required."] } }
```

**Kode Status:**
| Kode | Arti |
|---|---|
| 200 | Berhasil |
| 201 | Entitas baru dibuat |
| 400 | Validasi payload gagal |
| 401 | Token tidak ada/invalid/expired |
| 403 | Role/site scope tidak mencukupi |
| 404 | Resource tidak ditemukan |
| 500 | Server error |

## 5. Endpoint Krusial per Modul

### Modul: Users
| Method | Endpoint | Deskripsi |
|---|---|---|
| GET | `/users` | List user (`?page&limit&active`) |
| POST | `/users` | Buat user (role dibatasi sesuai §3) |
| PATCH | `/users/{id}` | Update user |
| DELETE | `/users/{id}` | Nonaktifkan (soft delete) user |
| POST | `/users/{id}/reset-password` | Reset password user oleh admin |

### Modul: Sites
| Method | Endpoint | Deskripsi |
|---|---|---|
| GET | `/sites` | List site (scoped by role) |
| POST | `/sites` | Buat site baru — **SUPER_ADMIN saja** |
| PATCH | `/sites/{id}` | Update site |
| DELETE | `/sites/{id}` | Nonaktifkan site — **SUPER_ADMIN saja** |
| GET | `/sites/{siteId}/officers` | List petugas ditugaskan ke site |
| POST | `/sites/{siteId}/officers` | Assign petugas ke site |
| DELETE | `/sites/{siteId}/officers/{userId}` | Hapus penugasan petugas |

### Modul: Checkpoints
| Method | Endpoint | Deskripsi |
|---|---|---|
| GET | `/checkpoints` atau `/checkpoints/{siteId}` | List checkpoint |
| POST | `/checkpoints` | Buat checkpoint (auto-generate `qrPayload`) |
| PATCH | `/checkpoints/{id}` | Update checkpoint |
| POST | `/checkpoints/{id}/qr/rotate` | Rotasi/regenerate QR token |
| GET | `/checkpoints/{id}/qr` | Download QR PNG (binary, untuk cetak) |

### Modul: Inventory
| Method | Endpoint | Deskripsi |
|---|---|---|
| GET | `/inventory?siteId=` | List inventaris per site |
| POST | `/inventory` | Tambah item |
| PATCH | `/inventory/{id}` | Update item |
| DELETE | `/inventory/{id}` | Hapus item |

### Modul: Reports (Review Laporan Patroli)
| Method | Endpoint | Deskripsi |
|---|---|---|
| GET | `/reports/visits` | List kunjungan patroli (`?siteId&condition&reviewStatus&from&to&page&limit`) |
| PATCH | `/reports/visits/{id}/review` | Review satu kunjungan (`status`: REVIEWED/ACKNOWLEDGED/ESCALATED/RESOLVED) |
| PATCH | `/reports/visits/bulk-review` | Bulk review (`ids[]` maks 200, `status`) |
| DELETE | `/reports/visits/{id}` | Hapus log kunjungan |
| GET | `/reports/summary` | Metrik ringkas untuk dashboard |
| GET | `/reports/compliance` | Laporan kepatuhan per site/officer |
| GET | `/reports/visits/export` | Export CSV kunjungan patroli |

### Modul: Live Command Centre
| Method | Endpoint | Deskripsi |
|---|---|---|
| GET | `/patrols/sessions/active` | Sesi patroli yang sedang berlangsung (untuk live map/dashboard) |

### Modul: LogBooks (Buku Mutasi)

|---|---|---|

## 6. Catatan Implementasi Frontend

- Semua request setelah login **wajib** menyertakan header `Authorization: Bearer <accessToken>`.
- Tangani `401` dengan alur: coba `POST /auth/refresh` sekali → jika sukses, retry request asli → jika gagal, hapus token & redirect ke `/login`.
- Tangani `403` dengan pesan yang membedakan dua kasus: (a) role tidak mencukupi, (b) `ADMIN` mencoba akses site di luar assignment — tampilkan pesan spesifik untuk kasus (b) agar tidak membingungkan user.
- Field pagination (`page`, `limit`, `total`, `totalPages`) konsisten di semua endpoint list — buat satu komponen pagination reusable.
- Enum penting untuk UI (badge warna, filter dropdown):
  - `condition`: `AMAN` (hijau), `WASPADA` (kuning), `DARURAT` (merah)
  - `reviewStatus`: `PENDING`, `REVIEWED`, `ACKNOWLEDGED`, `ESCALATED`, `RESOLVED`
  - `role`: `SUPER_ADMIN`, `ADMIN`, `SUPERVISOR`, `OFFICER`
  - `logbook status`: `ACTIVE`, `CLOSED`, `ACCEPTED`
  - `log entry category`: `BARANG_MASUK`, `BARANG_KELUAR`, `MONITORING`, `KERUSAKAN`, `POTENSI_BAHAYA`, `INSIDEN`, `LAINNYA`
